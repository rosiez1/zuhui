# 实验一部分

## 一、本轮实验概述
本轮主要围绕QKVCOMM论文中的跨模型通信部分推进实验实现，重点完成了两件事：
1. 将原先隐式的 KV 提取、量化、注入流程，封装为显式的 `sender -> payload -> receiver` 通信结构。
2. 接入 `Qwen/Qwen2.5-1.5B-Instruct`，并尝试实现 `TinyLlama/TinyLlama-1.1B-Chat-v1.0 -> Qwen/Qwen2.5-1.5B-Instruct` 的异构模型 KV cache 通信路径。

## 二、已完成代码实现
### 1. 显式通信封装
当前通信流程为：
```text
Sender model 处理上下文
-> 提取 past_key_values
-> adaptive / uniform 量化
-> bit packing
-> 构造 QKVCommPayload
-> Receiver 接收 payload
-> 反量化 KV
-> 注入 receiver model
-> 继续生成
```
### 2. Qwen2.5 模型接入
Qwen2.5 KV 结构：
```text
num_hidden_layers = 28
num_key_value_heads = 2
head_dim = 128
```

TinyLlama KV 结构：

```text
num_hidden_layers = 22
num_key_value_heads = 4
head_dim = 64
```
TinyLlama 的 KV cache 不能直接注入 Qwen，需要异构 calibration 和 shape adapter。

### 3. 异构模型 Calibration
当前按原论文实现的跨模型 calibration：
```text
TinyLlama KV
-> scalar mean/std 对齐
-> layer mapping
-> head/head_dim shape adapter
-> Qwen KV-compatible cache
```

#### 3.1 标量均值/方差对齐

对每层 K/V 计算：

```text
mean, std
```

然后使用论文中的统计对齐思路：

```text
KV_calibrated = (KV_source - mean_source) / std_source * std_target + mean_target
```
#### 3.2 层映射

TinyLlama 有 22 层，Qwen2.5 有 28 层。

当前采用线性 layer mapping：

```text
TinyLlama 22 layers -> Qwen 28 layers
```

#### 3.3 Shape Adapter

TinyLlama KV shape：

```text
[batch, 4, seq_len, 64]
```

Qwen2.5 KV shape：

```text
[batch, 2, seq_len, 128]
```

当前使用插值方式做 shape adapter：

```text
KV heads: 4 -> 2
head_dim: 64 -> 128
```

这一步主要保证张量形状能被 Qwen 接收。

### 2. 压缩结果

```text
original_past_key_values_bytes = 653312

```

说明 adaptive quantization 仍然有效减少了 KV payload 大小。

### 3. 长生成时的问题

当 `max_new_tokens = 20` 时，输出出现明显重复：

```text
A key advantage is used to is used to is used to is used to is used in is used in is used in
```

这说明当前异构 KV 注入虽然能跑通，但生成质量较差。

## 四、当前跨模型通信方法总结

当前 TinyLlama -> Qwen2.5 通信本质上采用的是：

```text
zero-shot statistical calibration + shape adapter
```

也就是：

1. 不训练额外参数。
2. 不学习 TinyLlama 到 Qwen 的真实语义映射。
3. 只通过统计分布对齐和张量形状变换，让 TinyLlama KV 能被 Qwen 接收。

当前方法可以概括为：

```text
让 KV “形状像 Qwen”
让 KV “数值分布像 Qwen”
但不能保证 KV “语义空间像 Qwen”
```

## 五、效果较差的原因

### 1. 均值/方差对齐能力太弱

mean/std 只能调整整体数值范围，无法对齐高维语义方向。

Qwen 的 query 会和传入的 key 做 attention dot product。如果 key 的语义方向没有对齐，即使均值和方差接近，attention score 也不一定有意义。

### 2. Shape adapter 只是工程适配，不是语义映射

当前把 TinyLlama 的：

```text
[4 heads, 64 dim]
```

插值成 Qwen 的：

```text
[2 heads, 128 dim]
```

这只是让张量 shape 对上，不能保证 TinyLlama 的 attention head 和 Qwen 的 attention head 有正确语义对应关系。

### 3. 层语义不一定对应

TinyLlama 第 10 层和 Qwen 第 13 层不一定处在相同抽象阶段。当前线性 layer mapping 只是一个简化假设。

### 4. Tokenizer 和 RoPE 差异会破坏 KV 兼容性

KV cache 不是普通 embedding，它绑定了：

```text
token 序列
position_ids
RoPE 相位
attention head 结构
```

TinyLlama 和 Qwen 的 tokenizer、position 编码细节、训练分布不同，都会导致 KV cache 难以直接迁移。

### 5. Qwen 接收到的是 out-of-distribution KV

对 Qwen 来说，校准后的 TinyLlama KV 并不是它训练过程中自然产生的内部状态。

因此 Qwen 后续生成时容易出现：

```text
重复
退化
语义不稳定
```

## 六、本次实验结论
### 可信部分

同构模型 KV 通信是比较可信的：

```text
TinyLlama -> TinyLlama
```

原因是：

```text
模型结构一致
tokenizer 一致
层数一致
head 语义一致
RoPE 设置一致
KV 空间一致
```

因此同构情况下，KV cache 量化、传输、反量化、注入是合理的。

### 存疑部分

异构模型 KV 通信目前效果较弱：

```text
TinyLlama -> Qwen2.5
```

当前实验说明：

```text
路径可以跑通
但语义质量不好
```

因此，论文中声称仅靠 zero-shot calibration 就能稳定实现异构模型 KV 通信，需要谨慎看待。

## 一、本轮实验概述
围绕 ComprExIT 论文中的跨层信息传输思想，在现有 qkvcomm 项目中完成了两条自适应量化策略的 demo 接入，并补充了基于 MRQA/SQuAD 的小规模 QA 评测链路。
主要完成内容如下：
1. 新增 MRQA/SQuAD 小规模 EM/F1 测评脚本。
2. 新增 `KV+Hidden mix` 自适应量化策略。
3. 新增 `hidden only` 自适应量化策略。
4. 使用 SQuAD dev 小样本进行 200 题评测，并分析当前指标反映的问题。

## 二、SQuAD 小规模测评

### 2.1 测评指标
- EM：Exact Match，标准化后预测答案与任一 gold answer 完全一致。
- F1：预测答案与 gold answer 的 token-level overlap F1。
### 2.2 测评配置
```json
{
  "max_contexts": 50,
  "max_questions": 200,
  "max_questions_per_context": 4,
  "max_context_tokens": 512,
  "max_new_tokens": 16,
}
```
### 2.3 测评结果

| mode | EM | F1 | Delta EM vs baseline | Delta F1 vs baseline | 平均压缩率 | 平均 bit |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 12.00 | 35.08 | 0.00 | 0.00 | 1.00x | - |
| uniform8 | 12.50 | 35.75 | +0.50 | +0.67 | 2.00x | - |
| adaptive864 | 15.50 | 35.12 | +3.50 | +0.04 | 2.63x | 6.09 |
| depth_aware864 | 15.50 | 35.41 | +3.50 | +0.33 | 2.63x | 6.09 |
| hidden_only864 | 16.00 | 32.92 | +4.00 | -2.16 | 2.63x | 6.09 |

### 2.4 结果解读
1. `uniform8` 与 baseline 非常接近。
   - 200 题中，`uniform8` 有 174 题的规范化 prediction 与 baseline 完全一致。
   - 说明 8bit uniform 量化基本在复现 baseline 行为，保真度正常。

2. `adaptive864` 和 `depth_aware864` 在 2.63x 压缩率下 F1 基本不掉。
   - `adaptive864` 的 F1 为 35.12，几乎等于 baseline 的 35.08。
   - `depth_aware864` 的 F1 为 35.41，略高于 baseline。
   - 这说明 8/6/4 分层量化在当前小样本下没有明显破坏 QA 输出。

3. `hidden_only864` 的 EM 最高，但 F1 明显下降。
   - EM 为 16.00，高于 baseline 的 12.00。
   - F1 为 32.92，低于 baseline 2.16。
   - 这说明 hidden-only 会产生更多“短答案直接命中”的情况，但也带来更多完全跑偏或低重叠答案，稳定性不足。

4. baseline 指标偏低的重要原因是答案格式。
   - baseline 有 136/200 题的 prediction 中包含 gold answer 子串。
   - 但其中 112 题由于预测答案过长，EM 仍然为 0。
   - 例如 gold 为 `Denver Broncos` 时，baseline 可能输出完整句子 `The American Football Conference (AFC) champion Denver Broncos.`，语义上包含正确答案，但 EM 会失败，F1 也会被多余 token 稀释。

### 2.5 当前测评暴露的问题

本轮 SQuAD 小样本评测主要暴露出以下问题：

1. TinyLlama-Chat 不是抽取式 QA 模型。
   - 模型倾向生成完整解释句，而不是短答案 span。
   - MRQA/SQuAD 的 EM/F1 对短答案格式非常敏感。

2. 当前 prompt 与后处理仍不够稳定。
   - 即使 prompt 中要求 short span，模型仍会输出解释性句子。
   - `prediction` 清洗规则能截断换行和明显 marker，但无法可靠抽取句子中的答案 span。

3. 当前样本属于小规模顺序抽样。
   - 样本来自 SQuAD dev 的前 50 个 context。
   - 后续应加入随机采样和固定 seed，降低顺序样本偏差。

4. hidden-only 策略缺少 KV 误差约束。
   - 它完全依赖 hidden states 计算层重要性。
   - 当前结果显示它会改变生成风格，但对 QA 正确性的稳定保留不如 KV+Hidden mix。

### 2.6 后续改进计划
1. 扩大评测规模。
   - 从 200 题扩展到 500 到 1000 题。
   - 先在 SQuAD dev 上稳定，再扩展到 NewsQA、HotpotQA、NaturalQuestionsShort 等 MRQA 子集。
2. 做小规模 LoRA SFT。
   - 目标不是让量化策略“看起来更好”，而是让 TinyLlama 学会 MRQA/SQuAD 的短答案格式。
   - 建议先用 MRQA train/SQuAD 取 5k 到 20k QA 进行 LoRA SFT。
   - SFT 后在 dev 集上重新比较 baseline、uniform8、adaptive864、depth_aware864、hidden_only864。

## 三、新增两种自适应量化策略

### 3.1 KV+Hidden mix 策略
该策略保留原有 KV cache 自适应量化框架，在层重要性评分中加入 hidden states 的跨层变化信息。

量化 bit 分配仍沿用 8/6/4：

- top 30% 重要层使用 8bit。
- middle 40% 使用 6bit。
- bottom 30% 使用 4bit。

### 3.2 Hidden only 策略
该策略只使用 hidden states 计算层重要性，不使用 KV norm、KV quantization error 或 middle prior。

量化 bit 分配同样使用 8/6/4。

# 论文部分
## 1. Cache-to-Cache：Direct Semantic Communication Between Large Language Models

### 核心思想

这篇论文提出 **C2C / Cache-to-Cache**，目标是让不同大语言模型不再只通过自然语言文本通信，而是直接通过 **KV-Cache** 进行潜空间语义通信。

传统多模型协作是：

```text
模型 A 理解输入 → 生成文本解释 → 模型 B 重新读文本 → 模型 B 推理
```

C2C 改成：

```text
模型 A 理解输入 → 提取模型 A 的 KV-Cache → 映射到模型 B 的 KV 空间 → 融合进模型 B 的 KV-Cache → 模型 B 解码输出
```

也就是说，模型 A 不需要把自己的“理解”压缩成文字，而是直接把内部表征传给模型 B。论文认为 KV-Cache 比文本更高维、更丰富，也避免了 token-by-token 生成通信文本带来的延迟。

### 工作流程

整体流程可以理解为：

```text
输入 X
 ↓
Sharer 模型 prefill，得到 Sharer KV-Cache
 ↓
Receiver 模型 prefill，得到 Receiver KV-Cache
 ↓
对 Sharer KV 和 Receiver KV 做 token / layer 对齐
 ↓
Cache Fuser 将 Sharer KV 投影并融合到 Receiver KV 中
 ↓
得到 Fused Receiver KV-Cache
 ↓
Receiver 基于融合后的 KV-Cache 直接 decode
 ↓
输出最终答案
```

其中：

* **Sharer**：提供额外语义理解的模型，例如代码模型、数学模型、大模型。
* **Receiver**：接收并利用这些潜空间信息的模型。
* **Cache Fuser**：核心模块，用来把 Sharer 的 KV-Cache 转换并融合到 Receiver 的 KV-Cache 中。
* **Gate 机制**：判断哪些层适合注入 Sharer 的信息，避免错误层的 KV 信息破坏 Receiver 原有表征。
* **LLM 本体冻结**：训练时不全参训练两个大模型，只训练 C2C 的投影与融合模块。

### 信息流动过程

C2C 的信息流本质是：

```text
Sharer 的潜空间语义信息
        ↓
KV-Cache
        ↓
跨模型空间映射
        ↓
Receiver KV-Cache 增强
        ↓
Receiver 解码生成
```

它实现的是 **跨模型潜空间语义增强**。Sharer 不直接给 Receiver 发送文本，而是把自己对上下文的内部理解以 KV-Cache 形式传递过去。Receiver 在解码时，相当于同时利用了自己的理解和 Sharer 的理解。

## 2. KVCOMM：Online Cross-context KV-cache Communication for Efficient LLM-based Multi-agent Systems

### 核心思想

KVCOMM 关注的不是异构模型之间的语义增强，而是 **多智能体系统中相同或相似文本被不同 agent 重复 prefill 的问题**。

在多 agent 系统中，不同 agent 可能使用相同模型，但有不同角色提示词。例如：

```text
Agent 1: 你是数学专家 + 用户问题
Agent 2: 你是验证专家 + 用户问题 + Agent 1 的回答
Agent 3: 你是代码专家 + 用户问题 + Agent 1 的回答
```

这些 prompt 中存在大量重叠内容，但因为前缀不同，同一段文本在不同上下文下产生的 KV-Cache 也会发生偏移，不能直接复制复用。KVCOMM 的核心就是：
**把跨上下文 KV 复用问题看成“KV 偏移估计问题”。**

### 工作流程

KVCOMM 的整体流程可以理解为：

```text
多 agent prompt 模板初始化
 ↓
预先缓存固定 prefix 的 KV
 ↓
新请求到来
 ↓
识别 prompt 中的可复用 placeholder，例如用户问题、上游 agent 输出
 ↓
查询 anchor pool，寻找相似历史样本
 ↓
估计当前上下文下的 KV offset
 ↓
修正共享文本的 KV-Cache
 ↓
拼接 prefix KV + 修正后的 placeholder KV
 ↓
跳过完整 prefill，直接 decode
 ↓
若无法复用，则 fallback 到正常 prefill，并把新样本加入 anchor pool
```

论文中的图 3 就是这个流程：每个 agent 有固定前缀段和动态 placeholder 段，KVCOMM 模块负责 anchor matching、offset approximation、cache update 和 anchor prediction。

### 信息流动过程

KVCOMM 中的信息流不是：

```text
Agent A 的理解 → Agent B 的理解增强
```

而更接近：

```text
共享文本的基础 KV-Cache
        ↓
结合历史 anchor 估计上下文偏移
        ↓
生成适配当前 agent 前缀的 KV-Cache
        ↓
当前 agent 直接 decode
```

也就是说，KVCOMM 传输的是 **可复用文本片段的 KV-Cache 及其上下文偏移规律**，重点是减少重复 prefill，而不是像 C2C 那样把一个异构模型的语义能力注入另一个模型。

## 3. 两篇论文简要总结
**C2C 更接近真正的跨模型潜空间语义通信**。它把一个模型的 KV-Cache 映射到另一个模型的 KV 空间中，通过 fuser 融合后让 Receiver 直接利用 Sharer 的内部理解。

**KVCOMM 更接近高效多 agent 通信系统中的 KV 复用机制**。它不是把一个模型的能力迁移到另一个模型，而是利用共享文本的 KV-Cache 和上下文 offset，避免不同 agent 对同一段内容反复 prefill。

一句话概括：

```text
C2C：模型 A 的“理解”传给模型 B。
KVCOMM：同一段文本的 KV-Cache 在不同 agent 上经过 offset 修正后复用。
```
